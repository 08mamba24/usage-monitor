# 配额数字统一显示剩余量

## 已接受的范围

用户指出：

> 为啥展开显示的百分比还是用量，应该改成剩余量比较统一？

随后明确保留简洁样式：

> 不用写字，也不用表明 cr啊，就原来的改下百分比是left就行

上一版已让亮色横条、亮色圆弧表示剩余量，却保留了列表与横条中的已用数字，
导致展开后数字与图形含义不一致。本次将 macOS 配额百分比数值统一为剩余量，
覆盖列表、刘海展开详情、周窗、MCP、横条与原生 tooltip。
保留原有简洁格式，不新增“剩余”“余”或 `left` 等百分比说明；积分主值不显示 `cr`。
这是现有显示逻辑的修正，不增加 Feature ID；Windows 保持冻结。

## 显示约定

- 主窗口原来显示 `5h 14% /2.5h` 时，现在显示 `5h 86% /2.5h`；
  刘海紧凑详情显示 `5h 86% 2.5h`。只改变百分比数值，不追加说明文字。
- 积分主值原来显示 `cr 62%` 时，现在仅显示 `38%`；`5h`、`7d`、MCP 等窗口标签、
  倒计时及其他元信息保留原样。
- 周窗、MCP 及其他配额窗口只转换原有百分比数值，例如 `MCP/mo 60%` 改为 `MCP/mo 40%`，
  保留 `/mo` 等单位。原有计数 `MCP/mo 278/1000` 保持原样，不改成百分比。
  悬停提示与对应可见标签保持一致；圆环悬停的百分比也不追加 `left`。
- 未使用时显示 `100%`，耗尽时显示 `0%`；百分比数值与亮色部分的长度一致。
- 已经表示剩余量的积分明细（如 `153/400 left`）保留原样，不重复反转或删除原有文字；
  余额、货币金额、套餐信息和错误提示
  按各自原有含义显示，不将其中的数字当作配额百分比转换。
  非 Claude 的次行若首先显示套餐信息（如 `pro`），也保留该元信息，不用后续窗口替换它。
- 横条继续左灰右亮，灰色从左向右增长；圆环灰色继续从 12 点顺时针增长。
  绿色、黄色、橙色、红色四档配色与风险含义保持一致。

## 数据与计算边界

后端 `Provider.pct`、`Win.pct` 仍表示已用百分比。消耗速度和历史采样继续使用已用值；
仅在 macOS 显示层转换配额数字，避免为了统一文字而改变风险等级、采样或数据接口契约。

  并验证余额、金额、套餐、既有剩余计数和无关百分比不被反转。
