# 横条剩余量与消耗方向

本记录保留方向调整版本当时的行为与验证；该版本仍显示列表/横条的已用数字。
用户随后要求百分比数值统一为剩余量、保留原简洁样式，当前约定见
[配额数字统一显示剩余量](2026-11-08-remaining-labels.md)。

## 已接受的范围

用户要求：

> 那现在的横条要不然改成，用掉的部分灰色，剩余的部分亮色，然后颜色和圆环一样，有绿色黄色红色？

随后明确方向：

> 还有现在圆环好像是逆时针消耗的灰色，改成顺时针；横条也是从左到右消耗

这是现有 macOS 监视器的显示增强。覆盖列表横条、刘海展开详情横条、紧凑横条和圆环；
Windows 保持冻结，不增加新 Feature ID。

## 显示约定

- 所有 macOS 横条将已用部分画为左侧灰色，剩余部分画为右侧亮色；
  使用量增加时，灰色从左向右增长，亮色从左侧逐渐缩短。
- 圆环的已用灰色部分从 12 点方向开始顺时针增长；其余亮色圆弧代表剩余量。
  外环、周窗内环和 MCP 虚线环采用同一方向。
- 未使用时，横条与圆环全部亮色；耗尽时全部灰色；部分消耗时同时展示两部分。
- “颜色和圆环一样”沿用现有绿色、黄色、橙色、红色四档。
  仍按消耗速度或已用百分比阈值选择颜色，不反转风险等级。
- 该版本的后端 `pct`、消耗速度计算、历史采样和列表/横条百分比数字仍表示已用量。
  圆环悬停中的剩余百分比继续明确标记 `left`。
- 取数失败与缓存数据的现有提示继续生效，避免将未知量画成充足配额。

## 变更前的行为

首次剩余圆环交付已将亮色圆弧长度改成剩余量；横条仍以亮色表示已用量。
本次统一横条的亮色含义，并明确圆环灰色顺时针、横条灰色从左向右的消耗方向。

## 验证结果

- RED：旧实现的 25% 已用圆环位图仍为右上亮、左上灰，方向回归测试明确失败。
- `./tests/run.sh` 通过：65 项 Python 测试及全部原生 Swift 回归。
  新检查覆盖圆环位图方向、三种横条视图的剩余宽度与右对齐、0/25/100% 和不可用状态、
  主/次窗口配色、MCP 透明度以及已用数字标签。
- 当前分支真实 `RingCell`、`BarCell`、`RowView` 和 `NotchDetailCell` 原生渲染已检查：
  25/50/75/90% 已用样例均为圆环灰色顺时针、横条左灰右亮，四色与圆环一致。
- 完整 macOS 优化编译、`git diff --check` 通过。
