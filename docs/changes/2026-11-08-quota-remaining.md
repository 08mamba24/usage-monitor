# 配额接口收尾与剩余圆环

本记录描述首次剩余圆环交付。横条显示与消耗方向的后续约定见
[横条剩余量与消耗方向](2026-11-08-meter-direction.md)。

## 已接受的范围

用户要求“把圆环改成按照剩余量显示，而不是用量显示”，并依次处理
“qoder日志，已有接口收尾，以及剩余量”。Windows 不再向外演进，内网改用 DSH 插件。
本次是现有监视器的修正与增强，不增加 Windows 能力。

## 结果与边界

- Qoder 测试固定采样时刻，不再依赖真实日期；验证到期前、到期时和到期后。
- Qoder 状态文件读写与相关测试关闭文件句柄，消除已复现的 ResourceWarning。
- Qoder 主池和资源包合并计算；仅资源包有容量也可显示。保留有限到期倒计时。
  实机返回的 `9999-12-31 UTC` 占位时间不再显示成 `exp 2912131d`，不据此推断终身权益。
- GLM 支持 `GLM_BASE_URL`，保留国际默认并支持本机已有的国内配置。
- CodeBuddy 读取 CLI 会话并以 POST 查询合并积分池；临期凭据隐藏，HTTP/业务错误不会显示成功。
- MiniMax 剩余 0% 正确转换为已用 100%，不再被默认值覆盖。
- 圆环外环、周窗内环和 MCP 虚线环使用剩余量；满环代表未使用，空环代表耗尽。
  悬停标记 `left`；颜色仍按消耗速度/已用阈值计算。此版本中，列表、条形图和数据契约仍为已用百分比。
- 单实例锁由对象持有至进程结束，创建配置目录、关闭竞争失败的句柄，exec 时不传给 Python。
  测试仅使用临时锁，避免原顶层守卫破坏测试编译或争用常驻锁。
- Windows 原代码与 CI 保留；F001 停止推进，F002 取消，未把真机验收记成通过。

## 验证依据

- 原始 RED：Python 56 项中 Qoder 到期测试失败；Swift 圆环绑定在已用 0% 时未得到满环；
  原单实例顶层 `do` 阻断测试编译，提取后首次临时目录加锁测试失败。
- 入口/边界测试覆盖 Qoder 仅资源包、MiniMax 零剩余、CodeBuddy POST/错误/临期凭据、
  状态文件读写往返与无资源警告。没有屏蔽 ResourceWarning。
- `./tests/run.sh` 通过：65 项 Python 测试与原生 Swift 回归，stderr 无资源警告；
  `git diff --check` 通过，完整 macOS 优化编译成功。
- 原生渲染使用当前 `RingCell.apply` 和 `MiniRingView.draw`，实看主环剩余 100/75/25/0% 的图像。
- 当前分支实机查询 GLM、Qoder 成功。CodeBuddy 当前会话不可用，按契约隐藏；
  其请求和失败路径由模拟 HTTP 验证，未声称已获得线上配额，未替用户登录或改凭据。

## 风险与复核

行为风险集中在剩余量转换、积分池合并、失败状态与单实例生命周期；已有回归覆盖。
保持后端 `pct=已用`，避免消耗速度和历史采样被反转。接口凭据只读复用，未新增认证刷新方式。
本次不迁移数据、不删除 Windows 实现、不改 Clowder AI 端口或 Redis。
